# Стратегии переноса TAP/TZX

Механизм загрузки отделён от сведений о конкретном дампе. Реализация находится
в `src/load_strategies.py`, единый каталог SHA-256 → профиль — в
`src/tape_catalog.py`, маршрутизация и специальные проверки — в `src/tape_profiles.py`, сборка диска — в `src/engine.py`.

## Каталог механизмов

| Стратегия в отчёте | Когда применять | Параметры и проверка | Проверенные примеры |
|---|---|---|---|
| `snapshot` | Все нужные данные загружаются до начала программы | Завершение ленты, отсутствие тайм-аута и пропущенных блоков; автоопределение модели по банкам и исполнению | Cosmic Payback, DuckTales, Valley of Rains |
| `rom-load-keyboard-safe` | Вступление читает клавиатуру между стандартными ROM LOAD | `in_flags=2`: опрос клавиатуры в RAM не запускает ленту; сами ROM LOAD выполняются | Fearzone 2018 |
| `snapshot-after-initialization` | Ранний снимок неудобен для упаковки либо программа сначала проверяет особенности машины | Адрес после распаковки/инициализации, `finish-tape=1`, требуемая модель, SP, порт 7FFD, сигнатура кода | Dizzy 7 NEW, Yazzie 128 |
| `snapshot-with-compatibility-patch` | Загруженный код несовместим с целевой машиной | Полный SHA-256, исходные инструкции и место вызова; только затем изменение RAM перед упаковкой | Escape trilogy: задержка вместо floating bus |
| `native-basic-chain` | BASIC загружает несколько самостоятельных частей и вызывает их через USR | Индексы блоков, размеры, адрес CODE, CLEAR, системная переменная ERR_NR, номер части для повторения | MILKY2, New View |
| `verified-resident-branch` | У кассеты есть альтернативные ветки, одна целиком помещается в RAM | Явная граница ветки и побайтная проверка всех нужных областей памяти | WEC Le Mans 128K |
| `unresolved-late-data` | После запуска остаются блоки, полноценный перенос которых не подтверждён | Отказ с причиной; неполный TRD не создаётся | Предоставленные Castlevania EN/RU, Dizzy 8 |

## Что можно переиспользовать

`SnapshotStrategy` формирует параметры эмулятора и проверяет точку сохранения.
Для другой игры с тем же типом загрузчика добавляется конфигурация с другим
адресом, моделью и сигнатурой. Код ожидания завершения загрузки менять не нужно.
Ожидание адреса само по себе не разрешает отбросить остаток ленты.

`NativeChain` проверяет заголовки CODE, адреса и размеры исходных частей.
`convert_native_chain` сохраняет сжатые части без изменений и создаёт компактный
BASIC-цикл с переменным именем файла. Размер BASIC почти не зависит от числа
частей: это оставляет TR-DOS рабочую память ниже CLEAR. Каждый дисковый LOAD
заканчивает строку, поскольку он следует за REM; USR находится на следующей
строке. Параметр `repeat_from` позволяет один раз показать вступление, а затем
повторять основную часть (MILKY2), либо пройти всю цепочку (New View).

Поиск профиля привязан к содержимому файла, а не к имени. Переименование TAP
не меняет результат. Другой дамп той же игры не наследует неподтверждённые
адреса и обходы. Неизвестные файлы используют обычную стратегию. Автоматическое
распознавание семейства загрузчика по сигнатуре можно добавить отдельно,
после проверки на нескольких независимых играх этого семейства.

## Порядок добавления поддержки

1. Сохранить SHA-256, структуру блоков и журнал исходного сбоя. Оригинал не менять.
2. Разделить причины: проверка файла, исполнение загрузчика, выбор модели,
   упаковка снимка, восстановление с TRD, подгрузка после старта.
3. Загрузить оригинал/эталонный снимок и диск в одном эмуляторе. Сопоставить
   регистры, память, банки и экран. Успех конвертера сам по себе недостаточен.
4. Выбрать существующую стратегию. Задать параметры в профиле и независимые
   проверки результата. Новый механизм добавлять только при иной схеме загрузки.
5. Проверить прямой запуск и запуск через меню. Для цепочки — каждую часть;
   для поздней подгрузки — именно момент подгрузки, а не только главное меню.
6. Добавить тест на причину сбоя, обновить отчёт совместимости и проверить
   несколько ранее работавших кассет. Не выдавать неподтверждённый перенос за готовый.

## Диагностика в программе

В журнале выводится название стратегии и пояснение профиля. JSON-отчёт содержит
`strategy`, `strategy_name`, `strategy_match`, `tape_profile` и дополнительные
сведения: количество частей, точку сохранения, выбранную модель, проверки банков.
`verified-sha256` означает узнавание проверенного дампа; `generic` — общий путь.
Это описание способа переноса, а не обещание прохождения игры до конца.

## Ограничения

«Tape finished» не гарантирует, что загрузчик использовал все данные. Пропущенные
блоки данных теперь приводят к отказу. Точно так же нельзя заставлять эмулятор
считать любое чтение клавиатуры чтением ленты: это может только прокрутить кассету,
не загрузив остаток. У Castlevania это воспроизведено при смене `in_flags=4` на `5`.

Z80to использует небольшую область под SP для восстановления регистров.
Проверки Fuse отдельно учитывают эту область в её физическом банке памяти,
в том числе при SP на границе 0xC000. Изменения вне неё не считаются допустимыми.
Проверка таймингов Yazzie по адресу 0xB2E5 может вызвать сброс на Pentagon;
общая стратегия ожидания инициализации выполняет её на исходной модели 128K
перед сохранением, не меняя код игры.

Тесты механизмов: `tests/test_load_strategies.py`. Прогоны новых дампов:
`scripts/audit_tricky10.py`; исходные и итоговые журналы находятся в
`.work/tricky-0.10/`. Итоговый отчёт и готовые тестовые диски — в
`output/tricky-0.10/`.


## Исправления совместимости Escape

`CodePatch` задаёт адрес, ожидаемые байты и замену. `SnapshotStrategy.adapt`
проверяет все сигнатуры до первой записи. Затем `prepare_snapshot` записывает
изменённый снимок и передаёт именно его упаковщику. Регистры, банки и остальные
данные сохраняются; исходная кассета не меняется. `compatibility_patches` в отчёте
содержит адреса, исходные сигнатуры и записанные байты.

Для трёх проверенных Escape цикл чтения `#40FF` заменяется задержкой из рабочей
дисковой демоверсии. Полное описание, адреса и границы проверки находятся в
[ESCAPE_COMPATIBILITY.md](ESCAPE_COMPATIBILITY.md). Совпадение имени игры не
включает патч. Повторное применение к уже исправленной RAM отклоняется проверкой
исходных инструкций; это не бесконтрольная замена похожих последовательностей.


## Добавление нового уникального дампа

1. Проверить структуру кассеты; вычислить SHA-256 всего файла. XOR каждого
   TAP-блока остаётся отдельной проверкой целостности.
2. Добавить запись `TapeProfile` в `src/tape_catalog.py`: уникальный ID,
   название, полный хеш, TAP/TZX, статус и описание RU/EN. Другой дамп той же
   игры получает собственную запись; имя файла не используется для совпадения.
3. Настроить существующую стратегию в `load_strategies.py` или добавить механизм
   для действительно другого типа загрузки. Неподтверждённый перенос пометить
   `unsupported`: он отклоняется до начала конвертации.
4. Добавить регрессию исходного сбоя и проверку результата; для патча проверить
   исходные байты и место вызова до записи. Поддерживаемая запись каталога
   обязана иметь реализованный обработчик — это проверяет тест каталога.
5. Выполнить `python scripts/generate_profile_help.py`, затем тесты и сборку.
   `build.ps1` обновляет справку автоматически. `--check` у генератора проверяет,
   что таблица не устарела. Редактировать таблицу в HTML вручную не нужно.

В таблице справки перечислены и готовые специальные способы переноса, и
явные ограничения. Статус `hardware-test` у Escape отделяет программную
проверку от ещё не выполненного запуска на целевой Дельте.
