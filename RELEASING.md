# Разработка и выпуск версий

Репозиторий: https://github.com/madcatse/TaRDulator .
Основная ветка — main. Для изменений используйте тематические ветки и pull request.
Исходники, справка, тесты и необходимые ресурсы хранятся в Git. Игры, локальные
ROM, эмулятор, зависимости и готовые сборки исключены через .gitignore.

## Проверки и архив

GitHub Actions (.github/workflows/windows.yml) на push в main, тег v* и pull request:

1. Устанавливает Python 3.12 x64 и зависимости через setup.ps1 на Windows 2022.
2. Проверяет актуальность справочного каталога, собирает GUI и движок,
   выполняет Python, C# graphics и WinForms UI проверки.
3. Проверяет автономный движок на искусственной ленте в режимах меню и прямого
   запуска, сравнивая TRD с результатом исходного Python-движка.
4. Создаёт полный переносимый ZIP и SHA256SUMS.txt, сохраняет их в артефакте
   Actions на 30 дней. В ZIP входят engine, help, licenses и соответствующие
   исходники, в том числе SkoolKit. BUILD_INFO.json связывает файлы с коммитом.

Локальный запуск (Windows, Python 3.12 x64, .NET Framework 4.8):

```powershell
.\setup.ps1
.\build.ps1
$env:PYTHONPATH = "$PWD\.tools\python-packages"
python scripts/check_release.py
python scripts/package_release.py
```

Для упаковки используйте чистую копию проекта. Скрипт отклоняет пользовательские
settings.json, игровые образы и кэш Python внутри переносимой папки.
Выходные файлы: releases-out/TaRDulator-vX.Y.Z-win-x64.zip и SHA256SUMS.txt.

## Новая версия

1. Измените VERSION в src/app_version.py — единый источник версии GUI, движка
   и упаковки. build.ps1 генерирует служебный .work/VersionInfo.cs.
2. Обновите CHANGELOG.md, README и releases/vX.Y.Z.md.
3. При изменении каталога запустите scripts/generate_profile_help.py и включите
   обе HTML-страницы в тот же коммит, что профиль и его проверки.
4. После слияния в main Actions собирает архив. Если есть releases/vX.Y.Z.md,
   создаётся черновик pre-release. Для заранее проверенного выпуска добавьте
   releases/vX.Y.Z.json с явными булевыми полями publish и prerelease:

       {"publish": true, "prerelease": true}

   publish=true публикует выпуск только после успешной сборки, тестов и проверки
   SHA-256; prerelease=true отмечает его предварительным. Без JSON по умолчанию
   создаётся только черновик. Для 0.10.1 публикация предварительного выпуска
   разрешена владельцем проекта. Видимость репозитория workflow не меняет.
5. То же работает при push тега vX.Y.Z или ручном Run workflow на main.
   Уже существующие релизы и их файлы workflow не изменяет. Для публикации
   существующего черновика используйте GitHub Releases. Для нового исправления
   увеличьте версию; для пересборки неопубликованного черновика удалите именно
   этот черновик и повторите workflow нужного коммита.
6. Сохраняйте опубликованные теги и архивы. Тег должен совпадать с версией
   исходников; BUILD_INFO.json в архиве содержит SHA исходного коммита.

## Совместимость

Новые исключения добавляются в src/tape_catalog.py по полной SHA-256 TAP/TZX.
Одного названия игры недостаточно. Патчи дополнительно проверяют сигнатуры кода.
Локальные тесты с личными TAP пропускаются в GitHub; сами игры не распространяются.
Для ошибок указывайте версию, SHA-256, модель машины и расширений, настройки и журнал.

Исправления Escape для Дельты 128К + AY пока требуют аппаратной проверки.
Успех на Spectaculator/Pentagon или Fuse её не заменяет. Этот статус должен
оставаться в каталоге, справке и описании релиза до реального подтверждения.

предварительная версия; общедоступный выпуск требует отдельного решения.
